# 「每日早安」闹钟 App 使用说明书

版本：2.2.0　|　适用系统：Android 10+（推荐 Xiaomi HyperOS 3.0）　|　包名：com.goodmorning.alarm

---

## 一、这是什么

「每日早安」是一款**音频闹钟 App**：每天在你设定的时间，自动播放你关注的抖音博主**最新视频的音频**；如果博主还没更新，就自动播放**最近一期**，并在界面上提示。

> 只播声音、不播画面——早上闭着眼也能听，无需打开抖音。
> 默认博主为「每日早安」，也可在设置页更换为任意抖音博主（支持历史一键切回）。

---

## 二、功能一览

| 功能 | 说明 |
|------|------|
| 每日闹钟 | 设定时间，每天重复；重启手机自动恢复；时间支持键盘直输 / 表盘双模式 |
| 自动播放 | 到点自动播最新视频音频；音量渐强（30%→100%，时长 5~60 秒可调） |
| 智能选片 | 当天更新 → 播当天；博主前一晚发布的次日视频自动识别为当天；未更新 → 播最近一期 |
| 副音频衬托 | 可选：响铃先循环播放自选背景音乐，衬托结束自动播视频音频并压低背景音；起点/终点/时长/音量全可调 |
| 播完自动重播 | 可选：整段播完未手动停止则自动从头再来，直到手动关闭 |
| 媒体控制卡 | 响铃时锁屏/通知栏出现媒体卡：暂停/继续（整场暂停）、拖动进度、停止、稍后提醒；HyperOS 超级岛同款渲染 |
| 三档同步 | 每天 05:30 / 12:00 / 21:00 自动同步并缓存最近视频，早上没网也能播 |
| 贪睡 | 1~30 分钟自由调节（默认 10）；贪睡后通知栏驻留下次响铃时间 |
| 四级兜底 | 本地缓存 → 系统闹钟铃声 → 系统铃声 → 蜂鸣音，**绝不哑火** |
| 博主管理 | 粘贴主页链接更换博主；历史博主一键切回；换博主自动清缓存重同步 |
| 日志导出 | 按天保留 7 天日志，可勾选任意日期多选导出（多选自动打包 zip） |
| 权限引导 | 首次启动分步引导完成 HyperOS 所需全部权限 |

## 三、安装

### 方式一：Android Studio 构建（推荐，可长期自己改）

1. 安装 **Android Studio**（自带 JDK，无需另装）
2. `File → Open` 打开工程文件夹 `goodmorning-alarm`
3. 首次 Gradle Sync 会自动下载依赖（工程已内置**阿里云镜像**，国内网络可直连；若仍很慢，检查电脑是否开着 Clash 等代理，建议先退出）
4. 手机开启「开发者模式」+「USB 调试」，数据线连接电脑
5. 点 **▶ Run** 安装到手机

**已知环境坑（Windows Git Bash）**：若在命令行用 `./gradlew` 报 `cygpath: unknown option -- quote`，改用以下命令直接编译：

```bash
export JAVA_HOME="<任意 JDK 17 路径>"
cmd //c "gradlew.bat assembleDebug"
```

### 方式二：直接安装 APK

拿到 `app-debug.apk` 后传到手机，点击安装（需在手机设置中允许「安装未知来源应用」）。

## 四、首次启动：5 步权限（决定闹钟能否正常响，务必完成）

打开 App 后按引导页逐项操作（每个按钮都会跳到对应系统设置页）：

| 步骤 | 权限 | HyperOS 手动路径 |
|------|------|-----------------|
| ① | 通知权限 | 弹窗直接点「允许」 |
| ② | 精确闹钟 | 系统弹窗允许；或 设置 → 隐私保护 → 特殊权限 → 闹钟和提醒 |
| ③ | 自启动 | 设置 → 应用设置 → 应用管理 → 每日早安 → 自启动（打开） |
| ④ | 省电策略 | 同上 → 省电策略 → 选「无限制」（否则可能被系统杀掉） |
| ⑤ | 全屏显示通知 | 特殊权限访问 → 全屏显示通知（打开，Android 14+ 才有此项） |

**额外建议**：在最近任务列表中下滑「每日早安」卡片并点击 🔒 上锁，防止误清后台。

## 五、日常使用

### 设置闹钟
主页 → 点击时间（键盘直输，可切表盘）→ 打开总开关 → 主页显示「下次响铃 HH:mm」与日出进度环。

### 设置页选项
| 选项 | 说明 |
|------|------|
| 博主管理 | 更换博主（粘贴主页链接或 sec_uid）；历史博主一键切回，× 删除历史条目 |
| RSSHub 地址 | 视频数据源地址（默认公共实例），见「常见问题 Q1」 |
| 贪睡间隔 | 1~30 分钟自由调节（默认 10） |
| 音量渐强 | 开/关 + 时长 5~60 秒可调（默认 20 秒） |
| 播完自动重播 | 整段播完未手动停止则自动再来，直到手动关闭 |
| 副音频衬托 | 开关 / 背景音乐文件 / 背景与压低音量 / 衬托时长（10 秒~10 分钟）/ 播放起点终点 |
| 立即同步 | 手动触发一次「拉取列表 + 下载缓存」，用于验证 |
| 清除缓存 | 删除已下载视频，释放空间 |
| 导出运行日志 | 弹窗勾选最近 7 天日志（可多选），多选自动打包 zip 分享 |

### 响铃时怎么操作
- **锁屏 / 通知栏媒体卡**：暂停/继续（整场暂停，含背景音乐）、拖动进度条定位、停止、稍后提醒
- **贪睡后**：通知栏驻留「下次响铃时间」，可滑动清除；到点自动再响
- **超级岛（HyperOS）**：响铃时岛上显示 App 图标 + 音频波形，点击展开控制

## 六、工作原理（简单版）

```
05:30 / 12:00 / 21:00  自动同步：拉取博主最新视频列表
        ↓              下载最近 2-3 条视频到手机本地（缓存）
     设定时间           精确闹钟触发（setAlarmClock，息屏/Doze 也能准点响）
        ↓
  选片：今天发布的 → 前一晚 18:00 后发布的（博主前夜发次日视频）→ 最近一期
        ↓
  （可选）背景音乐衬托 → 视频音频 + 渐强 → 播完可选自动重播
        ↓
  若本地文件损坏，逐级降级：本地缓存 → 系统闹钟铃声 → 系统铃声 → 蜂鸣音
```

- 闹钟**只依赖系统闹钟服务**，后台同步（WorkManager）只是提前备料，失败不影响响铃
- 重启手机后自动恢复闹钟；改系统时间也会触发重新校准
- 上游返回异常数据（错误账号/过期缓存）会被自动拦截，不写入本地

## 七、常见问题（FAQ）

**Q1：设置页「立即同步」报 EMPTY / PARSE / NETWORK 错误？**
公共 RSSHub 实例（rsshub.app）对抖音路由支持不稳定，这是已知现象，不影响闹钟响铃（会播缓存/铃声）。解决办法：
- 换其他公共实例地址（设置页修改后重新同步）
- 推荐**自建 RSSHub 或轻量代理**（见 Q2），一劳永逸

**Q2：怎么自建数据源？**
在一台**常开**设备（家里的旧电脑 / NAS / 虚拟机）上部署。除完整 RSSHub 外，本项目附带轻量代理
`dyproxy`（纯 Node，无第三方依赖，见 `dyproxy/README.md`）。

> ⚠️ **关键前提：必须部署在住宅宽带环境（家里），不要放在云服务器上。**
> 抖音的风控对**机房 IP** 会强制校验签名，云服务器直连一律返回 403；对**家宽 IP** 则完全免检。
> 若需要稳定的公网入口，用 frp 把家里的服务映射回云服务器即可（见 `dyproxy/frp/README.md`）。

```bash
# 家里那台 Linux 设备上（一键：装 Node + frpc、建 systemd 服务、设开机自启、跑自检）
sudo bash dyproxy/frp/setup-linux-vm.sh

# App 设置页数据源地址改为 http://<云服务器IP>:1200
```

> 🛌 **别忘了：这台设备要 7×24 开着。** 它一休眠/关机，App 就取不到最新视频
> （仍会播缓存，闹钟照响）。

**Q3：早上没网 / 断网时还会响吗？**
会。播放的是提前下载好的本地缓存；即便缓存也失败，还有铃声和蜂鸣兜底，闹钟一定响。

**Q4：博主当天没更新怎么办？**
自动播放最近一期。注意：博主常在**前一晚 23 点后**发布次日视频，选片会把它识别为当天内容。

**Q5：闹钟不准时 / 不响？**
依次检查：① 是否完成「自启动 + 省电无限制」；② 系统设置 → 精确闹钟权限是否允许；③ 是否把 App 加入了省电名单之外；④ 最近任务里是否被上锁。

**Q6：缓存占空间吗？**
最多保留最近 3 条视频（每条约 10-50MB），可在设置页手动清除。

**Q7：换手机 / 重装后设置会丢吗？**
闹钟时间、数据源地址、博主历史等设置需重新配置（未做云端同步）；缓存视频不迁移。

**Q8：副音频衬托是什么？**
响铃先循环播放你自选的背景音乐（如轻音乐），到设定衬托时长后自动播放视频音频，背景音乐压低音量继续陪衬；还可在已选音乐里裁剪播放起点/终点。不需要就关掉开关，直接播视频音频。

**Q9：播完了怎么又响了？**
开启了「播完自动重播」：整段播完后若未手动停止，会自动从头再来，直到按停止/贪睡。

## 八、技术信息

- 包名：`com.goodmorning.alarm`，minSdk 29 / targetSdk 35
- 技术栈：Kotlin + Jetpack Compose + Room + WorkManager + Media3 (ExoPlayer) + OkHttp + DataStore
- 单元测试：86 个 JVM 用例（选片 / 时间 / 解析 / 常量 / 同步参数）
- 项目文档：`docs/PRD.md`（需求）、`docs/ARCHITECTURE.md`（架构）、`docs/QA-REPORT*.md`（测试报告）
- 日志：App 内日志按天轮转保留 7 天（`filesDir/logs/`），设置页可多选导出
- 数据源代理：`dyproxy/` 目录（**须部署在住宅宽带环境**，云服务器 IP 会被抖音风控拦截；见其 README 与 `dyproxy/frp/`）
