# PRD：每日早安音频闹钟（GoodMorning Alarm）

## 1. 项目信息

| 项 | 内容 |
|---|---|
| 产品名称 | goodmorning_alarm（每日早安音频闹钟） |
| 平台 | Android App（单工程，交付 Android Studio 可直接 Run 的完整工程） |
| 目标设备 | 小米手机，Xiaomi HyperOS 3.0.303.0（Android 15 底层） |
| 语言 | 简体中文 |
| 技术栈（约束，已确认） | Kotlin + Jetpack Compose + AlarmManager（精确闹钟）+ WorkManager + Room + Media3/ExoPlayer |
| 原始需求复述 | 用户设定每天一个闹钟时间；到点后 App 自动播放抖音用户「每日早安」（抖音号 92588861148）当天最新视频的**音频**（不播画面，只播声音）；若当天未更新则播放最近一期缓存音频并提示「今日尚未更新，为你播放最近一期」；兜底链路：当天音频 > 缓存最近一期音频 > 本地铃声，绝不哑火。 |

**数据源与缓存约束（已确认，不可改动）：**
- 视频列表数据源：RSSHub 抖音用户视频路由；RSSHub 地址在 App 内**可配置**，默认填公共实例地址，用户可换成自建实例，无需改代码。
- 预下载：WorkManager 每天定时后台同步视频列表，并下载最近 2–3 条到本地缓存；闹钟响时播本地缓存，不依赖当时网络。
- 音频呈现方式：以**纯音频方式播放**（架构阶段在「ffmpeg-kit 提取音频」与「ExoPlayer 纯音频模式播 mp4」之间选型，PRD 不绑定实现）。
- HyperOS 适配：首次启动引导开启自启动、省电策略无限制、精确闹钟权限（SCHEDULE_EXACT_ALARM）、通知权限。

## 2. 产品定义

### 2.1 产品目标

**一句话**：让用户每天早晨被「每日早安」当天最新一条音频叫醒，稳定、准时、绝不哑火。

**衡量指标：**

| # | 指标 | 目标 |
|---|---|---|
| 1 | 闹钟准时触发率（到点 5 秒内出声） | ≥ 99%（HyperOS 权限按引导开启后） |
| 2 | 响铃零哑火率（三级兜底全失败） | = 0%，任何情况必须有声音 |
| 3 | 首次使用到成功设好闹钟的完成率 | ≥ 90%（权限引导 ≤ 4 步、≤ 2 分钟） |

### 2.2 用户故事

1. **首次使用引导**：作为新用户，我第一次打开 App 时，希望能被一步步引导开启自启动、省电无限制、精确闹钟和通知权限，以免闹钟被 HyperOS 杀后台而不响。
2. **设定闹钟**：作为用户，我希望设定一个每天重复的闹钟时间（如 07:00），并在主页清晰看到下次响铃倒计时，确认闹钟已生效。
3. **被叫醒**：作为用户，我希望闹钟到点时即使在锁屏状态，也能直达一个全屏播放页，听到「每日早安」当天最新视频的音频，并看到大字时间和视频标题。
4. **当天没更新的兜底**：作为用户，我希望即使该抖音号当天没发视频，闹钟也能播放最近一期音频，并明确提示「今日尚未更新，为你播放最近一期」，而不是没声音。
5. **换 RSSHub 源**：作为进阶用户，我希望在设置里把默认 RSSHub 地址换成自建实例，无需改代码、无需重新安装。

## 4. 关键交互流程

```
[设定闹钟] → [后台同步缓存] → [闹钟响铃] → [结束]
```

### 流程 1：设定闹钟（主页）
1. 主页默认展示：当前时间、闹钟时间选择器（TimePicker）、开关、下次响铃倒计时。
2. 用户设定时间并开启 → 请求/校验精确闹钟权限 → 注册 AlarmManager 精确闹钟（setExactAndAllowWhileIdle + 每日重复）。
3. 主页显示「明天 07:00 响铃」状态。

### 流程 2：后台同步缓存（WorkManager）
1. 每天定时（建议早晚各一次，如 06:00 前必跑一次，具体由架构定）后台任务。
2. 拉取 RSSHub 抖音用户视频列表 → 解析最近 2–3 条 → 下载到本地缓存目录 → 元数据（标题、发布日期、URL、本地路径）写入 Room。
3. 同步失败静默重试（下一周期兜底），不打扰用户；主页/设置可见最近同步状态。

### 流程 3：闹钟响铃（锁屏直达全屏播放页）
1. 到点 → AlarmManager 触发 → 启动前台服务 + 全屏 Activity（点亮屏幕、锁屏之上展示）。
2. 选片：查 Room 本地缓存 → 按 §5 规则选条目 → ExoPlayer 纯音频播放；若无任何可用缓存音频 → 播内置本地铃声（兜底）。
3. 播放页元素：
   - 大字当前时间（ HH:mm ）
   - 视频标题 + 发布日期
   - 播放/暂停控制
   - 「稍后提醒」（贪睡）
   - 「停止」（结束本次响铃）
   - 若播放的是缓存最近一期：顶部提示条「今日尚未更新，为你播放最近一期」
4. 铃声通道走闹钟音量（STREAM_ALARM / 音量类型 Alarm）。

### 流程 4：结束
- 点「停止」→ 停止播放、注销前台服务、重新注册下一次每日闹钟。
- 点「稍后提醒」→ 停止播放、注册 X 分钟后再次响铃（同一选片逻辑重跑一次，可能已更新缓存）。

## 5. 选片规则精确定义

**「当天」判定标准：视频发布日期（自然日） == 闹钟响铃日期（自然日）。**

详细规则：

1. **日期口径**：均取设备本地时区的自然日（yyyy-MM-dd），不使用 UTC。
2. **候选集**：Room 中已缓存的本抖音号视频，按发布时间倒序。
3. **优先级**：
   - ① 存在 `发布日期 == 响铃日期` 的视频 → 取其中**发布时间最新**的一条，标记为「今日音频」。
   - ② 不存在 → 取缓存中**发布时间最新**的一条（即最近一期），播放并在响铃页提示「今日尚未更新，为你播放最近一期」。
4. **发布日期来源**：以 RSSHub 条目的 pubDate 为准；若缺失/解析失败，视为无法判定「当天」，直接走规则 ②。
5. **多闹钟（P2）说明**：若同一天响铃多次，每次响铃均按上述规则重跑选片（后续新缓存的视频可被选中）。
6. **兜底**：Room 无任何缓存音频、或本地文件损坏/无法播放 → 播放内置本地铃声（第三级兜底）。

## 6. 待确认问题（请用户确认）

1. **贪睡时长**：稍后提醒默认间隔多久（建议 10 分钟）？是否需要可配置（5/10/15 分钟）？

## 7. Open Questions（内部，交架构阶段）

- ffmpeg-kit 提取音频 vs ExoPlayer 纯音频模式播 mp4：存储/解码/依赖体积权衡由架构决定。
- 抖音视频直链下载的时效性与防盗链策略（RSSHub 返回的链接是否可直接下载，需要架构阶段验证）。
- HyperOS 上 WorkManager 后台任务的实际执行可靠性（是否需提高同步频率作为补偿）。
